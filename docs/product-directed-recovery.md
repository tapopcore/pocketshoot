# Product-directed generation and recovery

This release addresses failures observed in real Makeup Locking Spray jobs. Front/back identity participates in Studio distinctness; visibly documented lateral coverage can be accepted from an angle-tagged original. A plan repair retains independently supported slots and records precise reasons for unsupported slots instead of discarding the whole useful set. Rejected raw plans remain in server-side job settings for diagnosis.

Campaign planning and delivery use durable job leases to avoid duplicate planning charges and stale parallel novelty comparisons. Manual retries reuse a prepared non-Studio brief. Budget-paused tiles regain recovery controls and no longer claim all tries were used. The existing server budget admission remains authoritative; no retry bypasses it.

Campaign commissions constrain customer purpose, environment and merchandise, while the director chooses product-specific light, composition, palette and gesture. Fixed three-pose and colour-wheel rotation is removed. Concise campaign render inputs carry the actual plan and relevant facts rather than repeating all product OCR. The image model, medium quality, maximum two originals and ₹5 admission ceiling remain unchanged.

The public homepage is unchanged. No training or guaranteed uniqueness is claimed. Reference-level quality requires visual evaluation; unit tests and compliance checks alone are insufficient.

Initial checks: 107 core tests, 129 web tests and TypeScript pass. Local production build hit the Windows native compiler path-access limitation; staged production-environment build and visual diagnostics are recorded separately before promotion.
